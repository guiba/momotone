# AGENTS.md - AI Assistant Context for gesture_rust

This document provides structural and architectural context to guide AI assistants in working with this codebase.

## Project Overview
`gesture_rust` is a real-time hand gesture recognition engine in Rust: OpenCV captures webcam frames, an **ONNX two-stage hand pipeline** (BlazeHand detector → landmark detector, via `ort`) produces a hand box plus 21 landmarks, a **strategy** turns those landmarks into a `GestureEvent`, and the **event bus** dispatches it to sinks (audio, MIDI) while an **iced dashboard** renders the live HUD.

> **Current status (Oct 2026):** the vision pipeline works end-to-end and `cargo check` passes (dead-code warnings only, no errors). The frame loop lives in `src/pipeline.rs` and runs on **its own thread**; `main.rs` hands the main thread to the **iced** dashboard (`src/dashboard/`), so rendering never blocks inference. `tokio` is now actually used (as iced's async executor, for the UI tick subscription). The detector stage is solid; the landmarker stage runs and returns 21 landmarks but is only lightly validated. Several modules (`sources/mock.rs`, unused strategies, the `Source`/`Tracker` traits, `Visualizer::draw_hud`) are scaffolding from earlier iterations.

## Tech Stack
- **Language**: Rust (Edition 2021)
- **Vision / inference**: `opencv` 0.100 (`clang-runtime` feature), `ort` 2.0.0-rc.13 (ONNX Runtime), `ndarray` 0.17
- **Audio**: `cpal` 0.17 (`Synthesizer` with a `Voice` sine oscillator)
- **MIDI**: `midir` 0.11 (`MidiOutputEngine`)
- **Messaging**: `crossbeam-channel` (unbounded MPMC) — the event bus
- **UI**: `iced` 0.14 (`canvas`, `image`, `tokio` features) — native dashboard window; `wgpu` renderer
- **CLI**: `clap` 4.5 (derive); `serde`/`serde_json` on the event types
- **Async**: `tokio` 1.36 (iced's executor); concurrency is `std` threads + `Mutex`/`Arc`/`AtomicBool`
- **Error handling**: `anyhow`

## Build Environment
- `.cargo/config.toml` forces `LIBCLANG_PATH` / `DYLD_LIBRARY_PATH` to `/opt/homebrew/opt/llvm/lib` (Homebrew LLVM) so the `opencv` build script finds clang. Do not remove it on macOS.
- OpenCV is built by the crate's build script on first compile; `target/` is ~1.7 GB and is gitignored.
- Quick verification loop: `cargo check` (≈4 s warm) rather than a full build.

## Core Architecture & Data Flow
One `Pipeline::tick()` per frame, driven by `Pipeline::run` on a dedicated thread:

```
WebcamSource.get_frame()  ->  HandTrackerImpl.process_frame()  ->  Strategy.process()
        (opencv)                 (ort: detector + landmarker)          (GestureEvent)
                                       |                                  |
                              FrameMetrics (Arc<Mutex>)          EventBus.dispatch() -> Sink.handle_event()
                                       |                          (Synthesizer / MidiOutputEngine)
                                 Dashboard (iced, main thread):
                                 canvas skeleton + telemetry rail
```

1.  **Input Phase**:
    *   `src/vision/camera.rs`: `WebcamSource::get_frame()` returns an OpenCV `Mat` (BGR); `new(camera_id, width, height)` requests a capture resolution (default 640×480). It does **not** implement the `Source` trait — that trait is currently unused scaffolding.
    *   `src/sources/mock.rs`: `MockSource` / `MockSourceImpl` are **dead code**. Mock mode is generated by `synthetic_detection()` in `src/pipeline.rs`, which builds an animated 21-landmark hand (no webcam, no ONNX assets) paced at ~30 fps.

2.  **Vision Phase** (`src/vision/tracker.rs`, `HandTrackerImpl`):
    *   Stage 1 — `run_detector()`: largest centred square of the frame resampled to **192×192** via `sample_affine_to_tensor(frame, Affine, w, h, &mut StageInput)` (OpenCV `resize` on the crop — `warpAffine` if it runs off the frame edge — then one bulk BGR→RGB `/255` pass). Each stage has a reusable `StageInput { warped: Mat, data: Vec<f32> }` allocated once in `HandTrackerImpl::new`, and ort is handed a zero-copy `TensorRef` view over `data`; the sampler returns the mapping it actually applied so the box/landmark conversion uses the snapped crop. Outputs 2016 boxes (18 values per anchor) + 2016 raw scores; scores are **sigmoid**-ed, argmax wins, gated by `HandTrackerImpl::score_threshold` (`DEFAULT_SCORE_THRESHOLD = 0.7`, overridable with `--score-threshold`).
    *   Anchor offsets are converted to frame pixels and the palm box is **expanded ×2** to cover the whole hand (`r#box` = `(x, y, w, h)` in frame pixels).
    *   Stage 2 — `run_landmarks()`: crops the box (side = max(w,h) × 1.2) into **224×224** and runs the landmark model; the 63 floats are mapped back to **frame pixel coordinates** (`Landmark { x, y, z }`). `--debug` prints the winning anchor, the landmark bbox and all 21 landmark coordinates.
    *   The tracker computes geometry only — it draws nothing. All overlays live in `src/visualizer/mod.rs`.
    *   Results are `HandDetectionResult { hand_landmarks: Option<Vec<Landmark>>, r#box: Option<(f32,f32,f32,f32)>, score: f32, timings: StageTimings }` (defined in `src/core/mod.rs`); `timings.detector_us` / `timings.landmarker_us` are measured per frame and feed the dashboard's performance card.

3.  **Strategy Phase** (`src/strategies/mod.rs`): implements `Strategy` from `src/core/mod.rs`.
    *   `FingerPositionStrategy` — the one used by `main.rs`. Index-tip Y normalised against the hand box → note **36–84**; thumb↔index distance → velocity/volume 0–1, where fingers spread apart is loud and a pinch is silent (saturates at `MAX_SPREAD = 0.6` of the hand box height). Unit tests in `src/strategies/mod.rs` cover the direction of the mapping.
    *   `SimplePinchStrategy` (thumb/index distance < 0.05) and `FrequencyStrategy` exist but are **not wired in**.

4.  **Orchestration** (`src/pipeline.rs`):
    *   `Pipeline::run` loops until an `AtomicBool` shutdown flag is cleared (set by `main` when the iced window closes) or `--max-frames` is hit; `Pipeline::tick` advances exactly one frame and publishes a `FrameMetrics` clone into `Arc<Mutex<FrameMetrics>>`.
    *   Sinks latch their last event, so `Pipeline::tick` tracks `gesture_active` and dispatches `GestureEvent::no_gesture()` (note 0) on the frame a gesture *ends* — without it the oscillator keeps sounding after the hand leaves.
    *   `src/core/event_bus.rs`: `EventBus::new()` returns `(EventBus, Receiver<GestureEvent>)`; `dispatch()` sends on a crossbeam channel. The pipeline drains it with `try_recv()` each tick and feeds the sinks.
    *   `src/core/types.rs`: `EventType { Continuous, Discrete }`, `GesturePayload { Signal { frequency, amplitude } | Note { note, velocity } }`, `GestureEvent { event_type, payload, text, color }` plus constructors `new_signal`, `new_note`, `no_gesture` (unused).
    *   `src/core/geometry.rs`: `hand_geometry()` derives resolution-independent descriptors (`spread`, per-finger `extension`, `tilt_deg`, `palm_length`) normalised by palm length. Strategies should reuse it instead of recomputing.

5.  **Output Phase** (implement `Sink`: `start`/`stop`/`handle_event`):
    *   `src/audio/synthesizer.rs`: `Synthesizer` — cpal output stream; shared `Arc<Mutex<SynthesizerState>>` between the callback and the event handler. `cpal::Stream` is wrapped in `StreamWrapper` with `unsafe impl Send/Sync`.
    *   `src/midi/mod.rs`: `MidiOutputEngine` — connects to a port whose name contains `--port` (default `OP-1`). Note payload is sent as `0x90, note + 60, velocity*127`.
    *   `src/visualizer/mod.rs`: OpenCV overlays, now used only by `--image` dumps. `draw_skeleton()` draws the bones + joint dots; `draw_hud()` is dead code since the iced dashboard replaced the on-frame HUD. Only landmark indices from MediaPipe's `HandLandmarksConnections` are drawn; the legacy `solutions.hands` cross-links ((9,4), (4,7), (4,10), (9,2), (13,5), (14,5)) are intentionally omitted because they assume an upright palm and render as stray lines on rotated hands.

6.  **Dashboard Phase** (`src/dashboard/`, iced 0.14, main thread):
    *   `dashboard/mod.rs`: `Dashboard` state (`boot`/`update`/`view`/`subscription`/`theme`). A `time::every(33 ms)` subscription produces `Message::Tick`, which takes the RGBA frame pixels out of the shared state (no copy) and clones the rest of the `FrameMetrics` into 120-sample ring buffers. Layout: window 1300x860; the skeleton stage on the left (the middle `row` is `.height(Length::Fill)` so the stage takes the whole middle band — a bare `row!` defaults to `Length::Shrink` and collapses it to the rail's intrinsic height), a live-numbers rail on the right (`OUTPUT`, `Volume`, `Confidence`, `PERFORMANCE`, `HAND GEOMETRY`, 300 px), and a bottom strip with the volume/confidence sparklines and the event log; `feed` / `box` / `labels` / `clear` buttons toggle overlays. The webcam image is only turned into an `image::Handle` when `show_feed` is on, so the RGBA upload is skipped by default.
     *   `dashboard/skeleton.rs`: the stage canvas program. By default it draws no camera image: `backdrop()` fills the panel with a vertical gradient (`PANEL_TOP` → `PANEL_BOTTOM`), a soft centre glow ringed outward to the panel colour, and a thin `STAGE_EDGE` outline of the letterboxed frame region. `keyboard()` turns that region into the instrument: `NOTE_COUNT` (49) semitone columns left→right (C2..C6), each tinted with its pitch class from `PITCH_COLORS`, separators brighter on the octave Cs, octave labels on the floor. A key's brightness comes from the UI's `note_trail` — a held key glows plus a volume bar rising from the floor, released keys fade out (top cap stays the most visible). The 21-point skeleton is then drawn on top through the same `Mapping` (frame pixels → letterbox), with a translucent palm hull (`PALM_HULL`), a wide translucent under-stroke per bone for the glow, and haloed fingertip joints. `feed` puts the webcam frame back into the letterbox rectangle; the detector box and finger labels are optional.
    *   `dashboard/gauges.rs`: `Meter` (level bar) and `Sparkline` (rolling trace) canvas programs.
     *   `dashboard/metrics.rs`: `FrameMetrics` (the only UI-facing struct), `EventLogEntry`, `note_name()` (MIDI → scientific pitch name, 60 = C4), `note_index()` / `note_frequency()` / `fade_trail()` for the keyboard trail (`NOTE_LOW = 36`, `NOTE_HIGH = 84`).
    *   Never block the UI: the tick handler only clones the snapshot; drawing is pure geometry.

## Running It
Models live in `gesture_rust/assets/` and are **gitignored** — they must be present locally or the tracker fails at startup. They come from the Unity/Sentis BlazeHand package (`mediapipe_hand_gesture-onnx-float.zip`; see `assets/new_readme.md`). Defaults:
`--detector-path assets/hand_detector.onnx`, `--landmarker-path assets/hand_landmarks_detector.onnx`, `--anchors-path assets/anchors.csv` (2016 anchors, normalised 0–1).

```bash
cargo run                                  # signal mode, audio output + dashboard
cargo run -- --mode midi --port OP-1       # MIDI output
cargo run -- --mode mock                   # synthetic animated hand: no webcam, no models
cargo run -- --no-ui                      # run the pipeline headless (no iced window)
cargo run -- --camera 1 --camera-width 1280 --camera-height 720   # different webcam / capture size
cargo run -- --debug                       # tracker diagnostics + a status line every 10 frames
cargo run -- --camera 1                   # pick a different webcam index

# Headless detection check without a webcam (best way to verify the box):
cargo run -- --image <any-photo-with-a-hand.png> --dump-frame output_frame.png --max-frames 1
```

Useful `Args`: `--mode signal|midi|mock`, `--amplitude` (audio master gain), `--score-threshold`, `--port`, `--image`, `--dump-frame`, `--max-frames`, `--camera`, `--camera-width`, `--camera-height`, `--no-ui`, `--debug`.

## Known Gaps / Things To Fix
See `ROADMAP.md` for the prioritised list of next features and performance work (effort-tagged).
- `Landmark.z` is read nowhere; `SimplePinchStrategy`/`FrequencyStrategy` are never constructed; `Visualizer::draw_hud` is unused.
- Unit tests cover the strategies, the resampling helper, the geometry helpers, the synthetic mock hand, the gesture **release** path in the pipeline and the synthesizer's voice lifecycle (`cargo test`); the bench is `#[ignore]`d. Still no lint/CI.
- The camera, inference and sinks share one pipeline thread; only the UI is separate. Splitting capture/inference/sinks into stages is still open (see ROADMAP).

## Development Guidelines for AI Assistants

### 1. Design Patterns
- **Trait-Based Abstraction**: To add a new output (e.g. OSC), implement `Sink` (`src/core/mod.rs`) and push it into the `sinks` vec in `main.rs`. New gesture logic means a new `Strategy` impl in `src/strategies/mod.rs`.
- **Coordinate discipline**: landmarks and boxes are always in **frame pixel space**, not normalised. Convert explicitly when feeding a model (192×192 detector, 224×224 landmarker) and convert back when drawing.
- **Error Handling**: Use `anyhow::Result` with `.context()`/`.with_context()` for model loading and frame I/O so failures name the file or stage.
- **Real-Time Constraints**: Keep `process_frame()` allocation-light; avoid blocking I/O (file writes, MIDI sends) inside the cpal audio callback — that callback must stay sample-rate safe.

### 2. Coding Style
- Follow standard Rust idioms (`rustfmt`/`clippy`), prefer explicit `?` over `.unwrap()`/`.expect()` in vision/audio paths.
- Treat the existing `unsafe impl Send for StreamWrapper` and `unsafe { ... }` pointer sampling as deliberate; add a comment explaining safety before touching them.

### 3. Never do these actions
- NEVER run `ls -R` — `target/` holds ~1.7 GB of dependency artifacts.
