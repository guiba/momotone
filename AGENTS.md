# AGENTS.md - AI Assistant Context for momotone

This document provides structural and architectural context to guide AI assistants in working with this codebase.

## Project Overview
`momotone` is a real-time hand gesture recognition engine in Rust: a pure-Rust capture stage reads webcam or MP4 frames, an **ONNX two-stage hand pipeline** (BlazeHand detector → landmark detector, via `ort`) produces a hand box plus 21 landmarks, a **strategy** turns those landmarks into a `GestureEvent`, and the **event bus** dispatches it to sinks (audio, MIDI) while an **iced dashboard** renders the live HUD.

> **Current status (Nov 2026):** the vision pipeline works end-to-end and the local gate `make verify` (check + test + fmt + `clippy --all-targets -D warnings`) is green; the only warning left is a third-party `block v0.1.6` future-incompat notice. The frame loop lives in `src/pipeline.rs` and runs on **its own thread**; `main.rs` hands the main thread to the **iced** dashboard (`src/dashboard/`), so rendering never blocks inference. `tokio` is used only as iced's async executor (`features = ["rt", "time"]`). The detector stage is solid; the landmarker stage runs and returns 21 landmarks but is only lightly validated. The scaffolding from earlier iterations (`sources/mock.rs`, the unused strategies, the `Source`/`Tracker` traits, `Visualizer::draw_hud`, `GestureEvent.event_type`) has been deleted.

## Tech Stack
- **Language**: Rust (Edition 2021)
- **Toolchain**: `rustc` / `cargo` 1.100.0 from the Homebrew `rust` formula (no `rustup` here — upgrade with `brew upgrade rust`), `rustfmt` 1.11.0, `clippy` 0.1.100. No C toolchain is required any more: the OpenCV dependency and with it the Homebrew LLVM / `libclang` requirement are gone.
- **Vision / inference**: `ort` 2.0.0-rc.15 (ONNX Runtime; still prerelease, there is no stable 2.0) — the model tensors are plain `Vec<f32>` buffers handed to ort as `TensorRef` views, so there is no array crate in the dependency list
- **Capture / decoding**: `nokhwa` 0.10 (`input-avfoundation`, `camera-sync-impl`) for the webcam — its bundled RGBA decoder is bypassed in favour of a hand-written YUYV pass — `mp4io` 0.1.2 + `rusty_h264-decoder` 0.17.2 for clips (both `#![forbid(unsafe_code)]`), and `image` 0.25 for still-image I/O
- **Audio**: `cpal` 0.18 (`Synthesizer` with a `Voice` sine oscillator). Note the 0.18 API: `build_output_stream` takes `StreamConfig` **by value** (it is `Copy`) and every backend returns a *paused* stream, so `stream.play()` is mandatory; all error types are unified into `cpal::Error` (`e.kind()`). Upstream 0.19 will rename `play()` to `start()` and merge `OutputCallbackInfo`/`InputCallbackInfo` into `CallbackInfo`.
- **MIDI**: `midir` 0.11 (`MidiOutputEngine`)
- **Messaging**: `crossbeam-channel` (unbounded MPMC) — the event bus
- **UI**: `iced` 0.14 (`canvas`, `image`, `tokio` features) — native dashboard window; `wgpu` renderer
- **CLI**: `clap` 4.6 (derive); `serde`/`serde_json` on the event types
- **Async**: `tokio` 1.36 floor (the lock resolves 1.54.1; iced's executor); concurrency is `std` threads + `Mutex`/`Arc`/`AtomicBool`
- **Error handling**: `anyhow`

## Build Environment
- Everything Rust-side is pure Rust; there is no native library to link against. `build.rs` links clang's compiler-rt on Apple targets only: fat LTO drops `___isPlatformVersionAtLeast` from `std`, which ONNX Runtime's CoreML object references (rustc issue #164915). Do not remove it if `cargo build --release` fails to link on macOS.
- `target/` is gitignored and is the only large artifact.
- Quick verification loop: `cargo check` (≈4 s warm) rather than a full build.
- The gate before any commit is `make verify` (`check` + `test` + `fmt --check` + `clippy --all-targets -D warnings`), mirrored on GitHub Actions by `.github/workflows/ci.yml` (push to `master` and every PR), which also runs a `--mode mock` smoke test that needs no camera and no models. `make help` lists the local targets.

## Core Architecture & Data Flow
One frame per iteration of `Pipeline::run`, on a dedicated thread:

```text
next_frame()  ->  advance()  ->  HandEstimator.update()  ->  Strategy.process()  ->  EventBus.dispatch()
(camera/mock)     (stages)       raw detection -> HandState   HandState -> Performance  -> Sink.handle()
                      |
                      +-- hand_over() -> Presenter (own thread): RGBA preview, ASCII art, dump/stdout
                      |
                      +-- publish() -> FrameMetrics (Arc<Mutex>) -> Dashboard (iced, main thread)
```

1.  **Input Phase**:
     *   `src/core/frame.rs` defines `Frame { width, height, pixels: Vec<u8> }` - **RGB, row-major** - the type that replaced OpenCV's `Mat` everywhere. `flip_horizontal()` mirrors in place by reversing each row's three-byte groups, and `to_rgba()` feeds the iced preview.
     *   `src/vision/camera.rs`: `WebcamSource::get_frame()` returns a `Frame` captured through `nokhwa`'s AVFoundation backend. The Mac webcam streams **YUYV (4:2:2)**; nokhwa's bundled RGBA decoder costs ~53 ms per 640x480 frame, so `yuyv_to_rgb()` is a hand-written indexed pass (~1.4 ms) that writes straight into the frame's buffer. Frames are mirrored by default so the stage behaves like a mirror (the user's right hand appears on the right, matching the keyboard's low-left/high-right layout); `--no-mirror` keeps the raw camera orientation. `new(camera_id, width, height, fps, mirror)` requests a capture resolution (default 640x480) and frame rate (default 30; best effort, `reported_fps()` returns what the driver actually gives).
     *   `src/vision/video.rs`: `VideoSource` decodes an MP4 with `mp4io` plus `rusty_h264-decoder`, both `#![forbid(unsafe_code)]`. It converts AVCC samples to Annex-B, prepends the SPS/PPS from the sample entry, reorders B-frames by picture-order-count into display order, and turns `yuv420p` into RGB with Rec. 601 coefficients. The YUV planes are bit-exact against ffmpeg on the fixture; the RGB lands within 2 LSB of ffmpeg's. **The decoder only supports 4:2:0**, which is why `make record` passes `-pix_fmt yuv420p`.
     *   Mock mode is generated by `synthetic_detection()` in `src/pipeline.rs`, which builds an animated 21-landmark hand (no webcam, no ONNX assets) paced at ~30 fps by a deadline clock. `FrameSource { Camera, Video }` is the source abstraction, and `next_frame` returns either a real frame or a synthetic one; everything downstream (`advance`) is identical for both.

2.  **Vision Phase** (`src/vision/tracker.rs`):
     *   `HandTracker` is an enum, `MediaPipe(Box<MediaPipeTracker>)` or `YoloPose(Box<YoloPoseTracker>)`, chosen by `--model` in `main.rs::build_tracker`. Both arms return the *same* `HandDetectionResult` (21 MediaPipe-ordered landmarks + a square hand box in frame pixels), so strategies, the dashboard and the annotator are model-agnostic. `process_frame` dispatches and then applies the shared landmark cache.
     *   `MediaPipeTracker` (formerly `HandTrackerImpl`) —
      *   Stage 1 - `run_detector()`: a **square window that follows the hand** (`detector_crop(palm, fw, fh)`) resampled to **192x192** via `sample_affine_to_tensor(frame, Affine, w, h, &mut StageInput, TensorLayout::Nhwc, border)` (`src/vision/sampling.rs`), a hand-written bilinear sampler that writes the `/255` float tensor in a single pass - no intermediate 8-bit image, no channel swap. Every mapping the pipeline builds is axis-aligned, so the sampler snaps the window to whole pixels and returns the *effective* mapping, which callers must use when converting model coordinates back to frame pixels; a window that hangs off the frame edge is filled with `border` (black for MediaPipe, Ultralytics' 114 for the letterboxed YOLO input). The side is `min(W,H)`; its origin is slid so it contains the palm centre seen last frame, clamped to the frame. With no history this is the centred square - at 640x480 that sampled only x = 80..560, which is why the outer keyboard keys were physically unreachable. The anchor is EMA-smoothed (`ROI_ANCHOR_WEIGHT = 0.3`) and dropped after `ROI_STALE_FRAMES = 10` consecutive misses (`note_miss`), so a hand that leaves the view does not pin the window. Each stage has a reusable `StageInput { data: Vec<f32> }` allocated once in `MediaPipeTracker::new`, and ort is handed a zero-copy `TensorRef` view over `data`.
      *   Which square the detector sees is `DetectorWindow { Anchored, FullFrame, Both }`, chosen by `--detector-window crop|frame|both`. `frame` letterboxes the whole image into the same 192x192 buffer, so anchors outside the crop are scored - the only way to find a second hand without a second model, and measured to cost the same as the crop (~8 ms either way). `both` keeps the crop as the behaviour, scores the frame alongside it, and prints the comparison at the end of the run (`HandTracker::probe_report`, `make probe` / `make probe-single` / `make probe-640`): detections, mean score, hands per frame at each gate in `SEPARATIONS`, and µs per detector pass. It is a measuring mode, not a playing mode - three detector passes per frame. Anchors above the gate are collected best-first and merged by `non_overlapping()` (greedy spatial NMS: accept a candidate only when its centre is more than `HAND_SEPARATION` x the larger palm radius from every accepted palm); `MAX_HANDS = 2` is the cap, and the separation sweep is what turned `HAND_SEPARATION` from a guess into a measured 1.0.
     *   Anchor offsets are converted to frame pixels and the palm box is **expanded ×2** to cover the whole hand. `run_detector` returns `PalmBox { cx, cy, half, score }`, and `r#box` is that square `(cx-half, cy-half, 2*half, 2*half)` reported **unclamped** - a constant size keeps the strategy's spread normalisation stable when the hand is clipped at the frame edge, and the canvas clips it when drawing.
      *   Stage 2 - `run_landmarks(frame, cx, cy, half)`: crops a square of side `half x 2 x 1.2` centred on the true palm centre (a hand clipped by the frame edge keeps its fingers in the crop; the part of the window outside the image is sampled as the border colour rather than sliding the crop off the hand) into **224x224** and runs the landmark model; the 63 floats are mapped back to **frame pixel coordinates** (`Landmark { x, y, z }`). `--debug` prints the detector window origin, the winning anchor, the landmark bbox and all 21 landmark coordinates.
     *   **Landmark reuse** (`ReuseCache`, moved out of the tracker into `src/vision/reuse.rs` and shared by both backends): if the palm centre moves less than `LANDMARKER_REUSE_MOVE_PX` (3 px) and its half-size by under 3 %, the previous keypoints are reused and the 224×224 model is skipped for that frame — at most `LANDMARKER_REUSE_MAX_FRAMES` (3) frames in a row, and the cache is cleared whenever no hand is found. `--landmarker-always` disables the fast path for A/B testing.
     *   `src/vision/yolo_pose.rs`: `YoloPoseTracker` — a **single-pass** Ultralytics pose model (YOLOv8/v11/YOLO26 hand-pose exports). `run()` letterboxes the frame to the model's square input via `letterbox_map` + `sample_affine_to_tensor(..., TensorLayout::Nchw, LETTERBOX_PAD)` (the padding is black, matching Ultralytics' own `letterbox`), runs one inference, and `decode_pose` picks the highest-scoring detection. `decode_pose` is layout-agnostic: it accepts both the attribute-major `(1, 69, 300)` head of YOLOv8/v11 and the detection-major, NMS-free `(1, 300, 69)` head of YOLO26, reads the leading `[x1,y1,x2,y2,conf(,class)]` values and the trailing 21 × (x, y, visibility) keypoints, and maps everything back to frame pixels through the inverse of the letterbox affine. The graph's own declared input size wins over `--pose-input` (static exports reject other buffer sizes, and the tracker prints why). Keypoint order is MediaPipe's, so nothing downstream changes. `timings.detector_us` is the whole inference; `landmarker_us` stays 0.
     *   Measured on an M-series CPU (debug build, 640×640, one frame): YOLO26 pose ≈ 70 ms/frame vs. the MediaPipe two-stage ≈ 20 ms. The pose model is ~41 MB FP32 (21 MB FP16) vs ~15 MB for the MediaPipe pair, and its confidences run low (≈0.48 on a clear palm photo), so `--score-threshold 0.3` is a sane starting point for `--model yolo`.
    *   The tracker computes geometry only - it draws nothing. Live overlays are drawn by the dashboard (`src/dashboard/skeleton.rs`); the offline `--image` overlay is `src/presentation/annotator.rs`.
    *   Results are `HandDetectionResult { hand_landmarks: Option<Vec<Landmark>>, r#box: Option<(f32,f32,f32,f32)>, frame_size: (usize,usize), score: f32, timings: StageTimings }` (defined in `src/core/mod.rs`); `frame_size` lets strategies normalise against the whole view. `timings.detector_us` / `timings.landmarker_us` are measured per frame and feed the dashboard's performance card.

3.  **Gesture Phase** (`src/gesture/`, implemented against `Strategy` in `src/core/mod.rs`): `main.rs` picks a strategy with `--gesture position|theremin`.
    *   `src/gesture/estimator.rs`: `HandEstimator::update(&HandDetectionResult) -> HandState { present, landmarks, hand_box, frame_size, confidence, tip, volume, proximity, proximity_ratio, approach, geometry, jitter_px }`. This is the single source of truth about the hand: it owns the confirm/grace gate, the fingertip EMA, the proximity EMA (and the approach rate derived from it), the geometry and the jitter measurement. Strategies read it and mutate nothing. `Pipeline::debounce` no longer exists - the gate lives here.
    *   `src/gesture/mod.rs`: the shared helpers - `band_position()` (the `NOTE_MARGIN`-inset playable band), `spread_volume()` (thumb-index distance -> 0..1, normalised by the hand box, deliberately a different denominator from `geometry::spread`), `proximity_ratio()` / `proximity_level()` (apparent palm size -> 0..1 loudness) and `volume_for()`, which picks between them according to `VolumeModel`. `TipSmoother` is gone; the smoothing constant is in the estimator only.
    *   **Loudness** is a model, not a gesture: `--volume proximity|pinch|blend` (`VolumeModel` in `src/core/instrument.rs`, a `LOUDNESS` picker in the dashboard rail). `proximity` is the default: `palm_length / min(frame_w, frame_h)` is resolution-independent, and perspective makes apparent size a direct proxy for distance - a hand twice as close is twice as big. The band is `--proximity-far` (0.05, silence) to `--proximity-near` (0.15, full volume); on the fixture clip the ratio runs 0.069..0.135, i.e. the whole sweep maps to 19 %..85 % volume. `blend` makes proximity the ceiling and the pinch decides how much of it is used. **Landmark `z` is deliberately unused for proximity**: the landmarker crops a palm-anchored square and resamples it to a fixed 224x224, so the hand always fills the crop and z arrives divided by the hand's own size - it describes how the fingers curl, not how far the hand is. `HandState::approach` is the smoothed rate of change of the proximity level (-1 backing off .. 1 charging in), the natural attack velocity for a future mapping. The index fingertip's **position** on a **degree x octave grid** selects the note: columns are the scale's degrees (left = low), rows are octaves (top = high). `GridLayout::new(root, scale, octaves)` (`src/core/grid.rs`) picks the octave placement that best centres the grid inside `NOTE_LOW..=NOTE_HIGH` (C2–C6) and stores the notes row-major, top row first. The playable band is inset by `NOTE_MARGIN = 0.10` on both axes, and the canvas draws cells with exactly the same inset, so the lit cell is the one the hand is over. With the default 5-degree x 3-octave pentatonic grid a cell is ~102 x ~86 px on a 640x480 frame, so jitter cannot cross a boundary. Thumb<->index distance still drives loudness when `--volume pinch` is selected (fingers apart is loud, a pinch is silent, saturating at `MAX_SPREAD = 0.6` of the hand box height); with the default proximity model it does not affect loudness at all. Unit tests cover both mappings, grid centring, corner clamping and the scale quantisation.
    *   `src/gesture/theremin.rs` — the continuous mapping: the tip's x sweeps `DEFAULT_LOW_HZ`..`DEFAULT_HIGH_HZ` (C2..C6, the same span the keyboard is allowed to reach) **logarithmically**, so half way across the frame is one octave up rather than half way in hertz, and nothing is quantised to a scale. Emits `Performance::Signal { frequency, amplitude }`, which the synthesizer glides and the MIDI sink ignores. `--theremin-low-hz` / `--theremin-high-hz` set the band.
4.  **Orchestration** (`src/pipeline.rs`): four stages on four threads.
    *   **Capture** (`capture_frames`) reads the webcam on its own thread into a **capacity-1 channel**; if inference is still busy, that frame is dropped and counted (`FrameMetrics::perf.dropped`) instead of letting the pipeline drift behind the camera. `Pipeline::run` takes the `WebcamSource` out of the struct for this.
    *   **Inference** is the pipeline thread: `run` loops until an `AtomicBool` shutdown flag is cleared (set by `main` when the iced window closes, and by `run` itself on exit) or `--max-frames` is hit, calls `next_frame()` and then `advance()` on the result, and publishes a `FrameMetrics` clone into `Arc<Mutex<FrameMetrics>>`. There is no second single-threaded path - the tests call `advance(synthetic_frame(..))` directly.
    *   **Sinks** run on a third thread that owns the `Receiver<BusMessage>`, so a blocking MIDI write cannot stall a frame. `sinks` is an `Arc<Mutex<Vec<Box<dyn Sink>>>>`; the pipeline thread only touches it to push a waveform change from the pickers.
    *   **Presentation** runs on a fourth thread (`src/presentation/presenter.rs`) draining a capacity-1 `PresentJob` channel. The frame thread only *moves* the frame into that channel, and only when something is watching (`Presenter::wanted`). RGBA conversion, the ASCII render, the terminal print and `--ascii-dump` all happen there.
    *   **Logging** is `tracing`, not `println!`. `main.rs::init_logging(debug)` installs one `EnvFilter` for the whole app: `INFO` by default, `DEBUG` with `--debug`, and `RUST_LOG` overrides both. There is no `debug: bool` on the tracker, the presenter or the pipeline - verbosity is decided once at the subscriber, and modules emit at a level without knowing who is listening. The libraries we do not control (`iced_winit`, `iced_wgpu`, `ort::logging`) are capped at WARN, so a plain `make run-release` prints the app's own startup lines and nothing else. Expensive diagnostics are guarded with `tracing::enabled!(Level::DEBUG)` so they are not computed for a filter that would drop them.
    *   **Control** lives in one place: `RuntimeConfig { active, feed, ascii, feed_fps, ascii_fps, ramp }` (`src/core/runtime.rs`), owned by the pipeline. The dashboard never writes it - it sends `UiCommand::{Start, Stop, SetFeed, SetAscii, SetRamp, SetInstrument}` down an unbounded crossbeam channel, and `advance()` drains the channel at the top of every frame. While `active` is cleared the capture thread sleeps and inference runs no frames, and `Pipeline::pause()` dispatches a release so the sinks go silent. The pipeline can also *shed* `feed` and `ascii` itself: `--budget-ms` (default `FRAME_BUDGET_MS` = 33.0) compares inference's p95 against the frame interval once a second, and on a breach clears both and logs the reason. The guard fires once and never overrides a manual toggle.
    *   `advance()` is five small stages - estimator `update`, `record_timing`, `update_modulation`, `update_tracking`, `dispatch_gesture`, `hand_over` - and then `publish` and `report_frame`. `update_modulation` is the effect chain's writer: it maps the hand's proximity, height, openness and horizontal position through `modulation_from_hand`, blends the result towards the previous frame with the `--fade-ms` time constant, and puts it on the bus only when `is_different` says it moved. With no hand the target is neutral, so a stage fades out instead of clicking off. Debouncing goes through `HandEstimator` + `DetectionGate` (`src/core/detection_gate.rs`, 2 confirm frames / 3 grace frames): the anchor score flickers around the threshold, so a raw compare would click the note on and off. Inside the grace window the previous keypoints are kept instead of releasing.
    *   `Pipeline`'s state is grouped: `RunFlags { max_frames, emit_frames }`, `Budget { limit_ms, shed }`, `Telemetry { started, last_publish, last_detection, avg_gap_ms, next_mock, the capture/inference/latency sample rings, the dispatch ring }`, `Presentation { jobs sender, presenter, stdout, dump }`, plus the stages themselves (camera, tracker, strategy, sinks, bus) and the estimator/gesture flags.
    *   `src/core/event_bus.rs`: `EventBus::new()` returns `(EventBus, Receiver<BusMessage>)`; `dispatch()` sends `BusMessage::Event(QueuedEvent { performance, dispatched_at })`, `dispatch_modulation()` sends `BusMessage::Modulation(Modulation)`, and `close()` sends `BusMessage::Shutdown` so the sink thread can block on `recv()` instead of polling.
    *   Stage timing lives in `FrameMetrics::perf`: `frame_ms` is inference time, `capture_ms` the camera read, `latency_ms` the capture-to-publish gap, and `fps` is derived from the interval between published frames (not from the stage times, which overlap). Percentiles of each stage are kept in `src/core/telemetry.rs` (`Samples`/`StageProfile`/`Latency`), recomputed every `PROFILE_REFRESH_FRAMES` (30) frames, printed at `INFO` at the end of a run and shown on the dashboard's Performance card as p50/p95/p99/max with an over-budget marker.
    *   `src/core/types.rs` (21 lines): `enum Performance { Note { note, velocity }, Signal { frequency, amplitude }, Release }`. That is the whole vocabulary between the gesture layer and the outputs - no `text`, no `color`, no `note == 0` sentinel, no `event_type`.
    *   `src/core/geometry.rs`: `hand_geometry(&[Landmark])` derives resolution-independent descriptors (`spread`, per-finger `extension`, `tilt_deg`, `palm_length`) normalised by palm length. Strategies should reuse it instead of recomputing.

5.  **Output Phase** (implement `Sink`: `start`/`stop`/`handle(&Performance)`, plus the optional `set_waveform` and `set_modulation`):
    *   `src/audio/synthesizer.rs`: `Synthesizer` — cpal output stream. The control side writes nine atomics (`Target { sounding, frequency, amplitude, waveform }` plus the chain: `enabled`, `cutoff_hz`, `vibrato_hz`, `vibrato_cents`, `delay_ms`, `feedback`); the callback owns a single monophonic `Voice` (target/current pitch, target/current amplitude, phase, timbre, and the chain state: one-pole filter state, LFO phase, delay ring) with a 12 ms attack, a 60 ms release and a 15 ms pitch glide, and **takes no lock, allocates nothing and makes no syscall**. The chain is read once per audio block, not per sample, and runs `glide -> vibrato -> oscillator -> one-pole lowpass -> comb delay -> soft clip`; vibrato rides on the glided pitch as a local `pitch` so it cannot leak into `self.frequency`. The 106 KB delay ring is allocated in `Voice::idle` when the stream opens. `cpal::Stream` is `!Send`, so it is wrapped in `StreamWrapper` with a documented `unsafe impl Send` - the one remaining `unsafe impl` in the project.
    *   `src/midi/mod.rs`: `MidiOutputEngine` — connects to a port whose name contains `--port` (default `OP-1`). `Performance::Note` goes through `NoteGate`, which enforces a `--min-note-ms` floor so a sweep across the keyboard is an arpeggio rather than 30 note-ons a second; `Release` sends exactly one note-off; `Signal` is dropped.
    *   `src/presentation/annotator.rs`: a pure-Rust skeleton overlay (Bresenham lines, filled discs) drawn onto the frame saved by the offline `--image` dump.
6.  **Dashboard Phase** (`src/dashboard/`, iced 0.14, main thread):
      *   `dashboard/mod.rs`: `Dashboard` state (`boot`/`update`/`view`/`subscription`/`theme`). A `time::every(33 ms)` subscription produces `Message::Tick`, which takes the RGBA frame pixels out of the shared state (no copy) and clones the rest of the `FrameMetrics` into 120-sample ring buffers. Layout: window 1300x860; the skeleton stage on the left (the middle `row` is `.height(Length::Fill)` so the stage takes the whole middle band — a bare `row!` defaults to `Length::Shrink` and collapses it to the rail's intrinsic height) and a **scrollable 320 px rail** on the right with two tabs: **basic** = `INSTRUMENT` pickers, `OUTPUT`, `RENDER` (the ASCII charset pick list), Volume, Confidence, Status; **advanced** = Performance, Hand Geometry, the volume/confidence sparklines and the event log. The header carries a chunky `Start`/`Stop` button (`big_button`, green/red) that flips the pipeline's `active` flag, plus smaller `feed` / `ascii` / `box` / `labels` / `clear` toggles (`small_button`). The webcam image is only turned into an `image::Handle` when `show_feed` is on, and only when the pipeline's `--feed-fps` cadence (default 15) has produced new pixels — the previous handle is kept in between, so the preview runs slower than the skeleton rather than uploading a 1.2 MB texture every tick.
      *   `dashboard/skeleton.rs`: the stage canvas program. By default it draws no camera image: `backdrop()` fills the panel with a vertical gradient (`PANEL_TOP` → `PANEL_BOTTOM`), a soft centre glow ringed outward to the panel colour, and a thin `STAGE_EDGE` outline of the letterboxed frame region. When the `ascii` toggle is on, `ascii_art()` fills the **whole panel** (not just the letterbox) with the camera as block glyphs: `cell_grid()` derives the glyph size from `GLYPH_ASPECT = 0.6` (a monospace glyph is 0.6 em wide and 1 em tall) so the rows tile the panel without stretching, and one `fill_text` run is emitted per row - the geometry cost is `rows` text runs, not `rows * cols`. A row's alpha comes from `AsciiGrid::row_mean`, and rows below `ROW_SILENT` are skipped entirely; the tint is the colour of the note being played - `backdrop_colour()` blends `PITCH_COLORS` over the keyboard trail weighted by level squared, so a held key paints the art its pitch class and a note change cross-fades over `--fade-ms`, falling back to the nearest key implied by a theremin frequency and, with nothing sounding, to neutral `MUTED` grey. The art is drawn *before* `keyboard()`, so the grid and the skeleton sit on top of it, and if `feed` is on too the webcam image is painted over the art. `keyboard()` turns that region into the instrument by drawing the `GridLayout`: cells inset by `NOTE_MARGIN` on both axes (the same band the strategy reads), tinted by pitch class from `PITCH_COLORS`, with octave rows separated by a heavier line and labelled on the left, and note names printed in each cell when the cells are big enough. A cell's brightness comes from the snapshot's `trail` (published by the frame loop, not the window) — the held cell glows and carries a volume bar rising from its floor, released cells fade out (top cap stays the most visible), with the decay time constant set by `--fade-ms` (`DEFAULT_FADE_MS = 450`, shown in the header as `trail 450 ms`). The 21-point skeleton is then drawn on top through the same `Mapping` (frame pixels → letterbox), with a translucent palm hull (`PALM_HULL`), a wide translucent under-stroke per bone for the glow, and haloed fingertip joints. `feed` puts the webcam frame back into the letterbox rectangle; the detector box and finger labels are optional.
        The stage is split into four layers in draw order: the cached backdrop, the ASCII art, the cached keyboard grid, and a final frame for everything that moves. `Keyboard::new(stage, layout)` computes the band and cell geometry as plain data (no iced), which is what the headless tests assert; `keyboard_grid()` draws the static cells/labels and `keyboard_trail()` the fading glow. `StageCache` (the program's `State`) holds the two `canvas::Cache` layers and clears them when the capture resolution or the instrument changes. The 21-point skeleton is then drawn on top through the same `Mapping` (frame pixels → letterbox), with a translucent palm hull (`PALM_HULL`), a wide translucent under-stroke per bone for the glow, and haloed fingertip joints. `feed` puts the webcam frame back into the letterbox rectangle; the detector box and finger labels are optional.

## Running It
Models live in `assets/` and are **gitignored** — they must be present locally or the tracker fails at startup. The MediaPipe pair comes from the Unity/Sentis BlazeHand package (`mediapipe_hand_gesture-onnx-float.zip`; see `assets/new_readme.md`). Defaults:
`--detector-path assets/hand_detector.onnx`, `--landmarker-path assets/hand_landmarks_detector.onnx`, `--anchors-path assets/anchors.csv` (2016 anchors, normalised 0–1).

```bash
cargo run                                  # signal mode, audio output + dashboard
cargo run -- --mode midi --port OP-1       # MIDI output
cargo run -- --gesture theremin             # continuous pitch instead of the keyboard grid
cargo run -- --mode mock                   # synthetic animated hand: no webcam, no models
cargo run -- --no-ui                      # run the pipeline headless (no iced window)
cargo run -- --camera 1 --camera-width 1280 --camera-height 720   # different webcam / capture size
cargo run -- --debug                       # DEBUG-level logging: tracker diagnostics + a status line every 10 frames
cargo run -- --camera 1                   # pick a different webcam index
cargo run -- --model yolo --score-threshold 0.3   # single-pass Ultralytics pose model instead of BlazeHand
scripts/get_pose_model.sh fp16            # fetch a pose ONNX into assets/yolo_hand_pose.onnx (fp32 by default)
cargo run -- --ascii                       # ASCII art backdrop, on from the start

# ASCII art without a window - the quickest way to eyeball the renderer:
cargo run -- --mode mock --no-ui --ascii --ascii-cols 70 --max-frames 100
cargo run -- --ascii-dump art.txt          # write each rendered frame to a file

# Headless detection check without a webcam (best way to verify the box):
cargo run -- --image <any-photo-with-a-hand.png> --dump-frame output_frame.png --max-frames 1

# Reproducible run against a locally recorded clip, checked against a golden trace:
make record           # 20 s from the webcam into fixtures/hand_clip.mp4 (ffmpeg, run once)
make fixture          # 120 frames of that clip, headless
make trace-check      # exits non-zero if the note/volume trace drifts
make trace            # rewrite fixtures/clip_trace.json from the current behaviour
make mock-trace-check # CI's gate: deterministic mock run, no camera, no models
```

`fixtures/` is gitignored: the clip is a recording of a real hand and is generated locally,
not shipped. The `#[ignore]`d `tracker_finds_the_hand_in_the_clip` and `bench_clip_decode`
tests need it too.

Useful `Args`: `--mode signal|midi|mock`, `--model mediapipe|yolo`, `--ort-threads` (ONNX Runtime intra-op threads; 0 = runtime default, measured fastest), `--pose-path`, `--pose-input` (the graph's own declared size wins; a static export prints why it ignored the request), `--amplitude` (audio master gain), `--score-threshold` (0.6 for BlazeHand, ~0.3 for the pose model), `--gesture position|theremin`, `--theremin-low-hz` / `--theremin-high-hz` (C2..C6 by default), `--port`, `--image`, `--dump-frame`, `--max-frames`, `--camera`, `--camera-width`, `--camera-height`, `--camera-fps` (default 30), `--feed-fps` (camera preview cadence, default 15; 0 = every frame), `--ascii` (start the ASCII backdrop switched on; the header button is the runtime toggle), `--ascii-cols` (default 140; rows follow the frame aspect), `--ascii-fps` (default 15; 0 = every frame), `--ascii-ramp blocks|shades|ascii|braille|dots` (the charset the run starts with - `blocks` is the only set guaranteed monospaced in SF Mono/Menlo, shades/dots/braille fall back to a non-monospaced font in iced but read beautifully in a terminal; the `RENDER` card changes it live, and the stdout print and dump follow the change), `--ascii-dump <path>` (write each rendered frame as text), `--no-mirror`, `--fade-ms` (keyboard trail time constant, default 450), `--scale` (default `major pentatonic`; also `minor pentatonic`, `major`, `minor`, `dorian`, `whole tone`, `chromatic`), `--root` (default `C`, accepts `F#`, `Bb` …), `--octaves` (grid rows, default 3; shrinks if the requested span cannot fit in C2–C6), `--waveform` (`sine`, `triangle`, `square`, `saw`), `--effects lowpass,vibrato,delay` (which stages are in the sound chain; default `lowpass`, `none` for a bare note, `all` for everything - the dashboard's EFFECTS card toggles them live), `--volume proximity|pinch|blend` (what decides loudness; proximity is the default, blend uses proximity as the ceiling and the pinch as the envelope), `--proximity-far` / `--proximity-near` (the palm-length-per-frame band, default 0.05..0.15; raise `near` if the hand has to be closer before it gets loud), `--min-note-ms` (MIDI voice floor, default 120 ms; 0 attacks on every cell change), `--landmarker-always` (run the landmark model on every frame), `--video <path>` (read a clip instead of the webcam, paced at the clip's own frame rate), `--trace <path>` (write the run's per-frame note/volume trace), `--expect <path>` (diff against a recorded trace and exit non-zero on a difference), `--budget-ms` (shed ascii/feed when inference's p95 exceeds it; default 33.0, the 30 fps frame interval; 0 disables the guard), `--no-ui`, `--debug` (sets the `tracing` level to DEBUG; `RUST_LOG` overrides it).

## Working conventions

The usual open-source Rust workflow. Deviating is fine with a reason in the commit message.

### Branches
- One topic per branch, named `feat/…`, `fix/…`, `perf/…`, `chore/…`, `ci/…` (the `phaseN-…` branches are the historical phase names from the rearchitecture).
- Branch off `master`, keep the branch short-lived, rebase onto `master` before opening the PR.
- `master` is always green: it passes `make verify` and CI at every merge.

### Commits
- **Conventional commits**: `feat:`, `fix:`, `perf:`, `docs:`, `test:`, `chore:`, `ci:` — with an optional scope, e.g. `fix(vision): …`.
- Subject in the imperative mood, ≤ 72 chars ("Add landmark reuse", not "Added"); body explains *why*, wrapped near 100 chars.
- One logical change per commit. A dependency bump that forces an API change is its own commit.
- Never commit `target/`, `assets/`, `.onnx`/`.zip`, screenshots or editor config — they are gitignored for a reason.

### Pull requests
- Small and focused: the diff should be readable in one sitting.
- The description says what changed, why, and **how it was verified** (which command you ran).
- CI must pass before merging; squash-merge keeps `master` one commit per feature.

### Tests
- Every new pure function gets a unit test in the same file under `#[cfg(test)]` — the dashboard aside, this codebase is tested where it is testable.
- A change to the gesture mapping is checked against the golden trace: `make trace-check`. Regenerate with `make trace` only when the change is intentional, and read the diff it produces first. The trace lives next to a locally recorded clip, so it is per-machine - the point is that a run does not change under a given recording, not that two recordings agree.
- Perf claims need numbers: run the `#[ignore]`d benches (`make bench`) and record them in `bench/baseline.md`.

### Dependencies
- `cargo update` is a standalone `chore(deps)` commit; if an upgrade forces an API change, the CHANGELOG says so.
- Prefer bumping a minor/patch of an existing crate over adding a new one. Keep `Cargo.lock` committed so CI and local builds agree.

### Documentation
- User-visible behaviour → README (flags table) plus a CHANGELOG entry under **Unreleased**.
- Architecture changes → the data-flow section of AGENTS.md, and ARCHITECTURE.md if it was a design decision.

### Releases
- Semantic versioning in `Cargo.toml`: mapping/API break = major, new feature = minor, fix = patch.
- Tag `vX.Y.Z` at release, move the **Unreleased** CHANGELOG section under that version, and cut a release branch only if you need to backport.
- Before publishing publicly, add a license (`Cargo.toml` currently has none) — MIT or Apache-2.0 are the usual choices for this stack.

## Development Guidelines for AI Assistants

### 1. Design Patterns
- **Trait-Based Abstraction**: To add a new output (e.g. OSC), implement `Sink` (`src/core/mod.rs`) and push it into the `sinks` vec in `main.rs`. New gesture logic means a new `Strategy` impl in `src/strategies/mod.rs`.
- **Coordinate discipline**: landmarks and boxes are always in **frame pixel space**, not normalised. Convert explicitly when feeding a model (192×192 detector, 224×224 landmarker) and convert back when drawing.
- **Error Handling**: Use `anyhow::Result` with `.context()`/`.with_context()` for model loading and frame I/O so failures name the file or stage.
- **Real-Time Constraints**: Keep `process_frame()` allocation-light; avoid blocking I/O (file writes, MIDI sends) inside the cpal audio callback — that callback must stay sample-rate safe.

### 2. Coding Style
- Follow standard Rust idioms (`rustfmt`/`clippy`), prefer explicit `?` over `.unwrap()`/`.expect()` in vision/audio paths.
- Treat the existing `unsafe impl Send for StreamWrapper` and `unsafe { ... }` pointer sampling as deliberate; add a comment explaining safety before touching them.

### 3. Never do these actions
- NEVER run `ls -R` — `target/` holds ~1.7 GB of dependency artifacts.
